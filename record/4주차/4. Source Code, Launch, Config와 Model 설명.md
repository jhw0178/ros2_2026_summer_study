## 4.2 Source Code 상세 설명

### 4.2.1 `aruco_homography_calibration.py`

| 기능     | 구현                                                                 | 설명                                                                                        |
| ------ | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| 카메라    | `gstreamer_pipeline()`                                             | `v4l2src → MJPEG 디코딩 → BGR appsink`, `drop=true max-buffers=1`로 최신 프레임 유지                 |
| 영상 발행  | `publish_image()`                                                  | cv_bridge 변환 및 1초 단위 실측 발행 FPS 로그                                                         |
| 좌표 변환  | `detection_callback()`                                             | JSON 파싱 → `perspectiveTransform` → type 필터 → 거리 정렬 → `target_point` + `nearest_target` 발행 |
| 검증 도구  | `mouse_callback()`                                                 | 화면 클릭 지점의 로봇 좌표를 m/cm 단위로 출력                                                              |
| 마커 관리  | `get_marker_center()` / `remove_old_markers()`                     | 4코너 평균 중심 계산 및 0.5 s hold 후 제거                                                            |
| 캘리브레이션 | `calculate_homography()`                                           | ID 1~4 확보 시 1회 계산 후 LOCK                                                                  |
| 시각화    | `draw_saved_markers()` / `draw_workspace()` / `draw_camera_axis()` | 마커, 작업영역, 원점, 픽셀 축 표시                                                                     |
| 리셋     | `reset_calibration()`                                              | H 및 마커 캐시 초기화                                                                             |
| 메인 루프  | `run()`                                                            | 캡처 → 발행 → 검출 → 계산 → 표시 → `spin_once(0.0)`                                                 |

### 4.2.2 `detector.py`

| 기능     | 구현                                                 | 설명                                                  |
| ------ | -------------------------------------------------- | --------------------------------------------------- |
| 영상 수신  | `image_callback()`                                 | `np.frombuffer` + `step` 고려 reshape                 |
| FPS    | EMA                                                | `0.9 / 0.1` 방식으로 FPS 계산                             |
| 결과 변환  | `convert_result()`                                 | supervision으로 결과 파싱 → threshold 필터 → bbox 밑변 중앙점 계산 |
| 추론 실행  | `run_paper()` / `run_pet()` / `run_can()`          | 모델별 추론 및 예외 격리                                      |
| 비동기 관리 | `update_inference_results()` / `start_inference()` | 완료 Future 수거 및 idle 모델에 최신 프레임 제출                   |
| 시각화    | `draw_predictions()`                               | bbox + 기준점 + 픽셀 좌표 + 클래스/confidence                 |
| 발행     | `publish_detections()`                             | 3종 결과 병합 JSON 발행                                    |
| 정리     | `cleanup()`                                        | executor shutdown 및 GUI 종료                          |

### 4.2.3 `robot_control.py`

| 기능    | 구현                        | 설명                                           |
| ----- | ------------------------- | -------------------------------------------- |
| 목표 수신 | `target_callback()`       | JSON 파싱 → type/작업영역 검증 → lock을 통한 스레드 안전 저장  |
| 목표 조회 | `get_current_target()`    | 2 s 신선도 검사                                   |
| 좌표 보정 | `apply_distance_weight()` | 기준거리 0.308 m 대비 near/far 비대칭 선형 보정           |
| 자세 계산 | `get_safe_pose()`         | joint1 임의 + 비행 자세(-35°, -30°) + joint4 수평 유지 |
| 근사 IK | `simple_ik_solver()`      | 선형 근사식 기반 IK                                 |
| 팔 제어  | `send_arm_trajectory()`   | 단일 waypoint goal 비동기 송신 + sleep 동기화          |
| 그리퍼   | `control_gripper()`       | position + `max_effort=100`                  |
| 시퀀스   | `execute_pick_sequence()` | 12단계 Pick & Place                            |
| 메인    | `main()`                  | spin 전용 데몬 스레드 + CLI `input()` 동시 처리         |

# 4.3 Launch 파일

`launch/waste_sorting.launch.py`

```python
from launch import LaunchDescription
from launch_ros.actions import Node


def generate_launch_description():
    return LaunchDescription([
        Node(
            package='waste_sorting',
            executable='aruco_homography_calibration',
            name='aruco_homography_calibration',
            output='screen',
        ),

        Node(
            package='waste_sorting',
            executable='detector',
            name='waste_detector',
            output='screen',
        ),

        Node(
            package='waste_sorting',
            executable='robot_control',
            name='waste_pick_node',
            output='screen',
        ),
    ])
```

> 실제 환경에서는 GUI와 CLI 입력이 각각 필요하므로 터미널을 분리 실행하는 방식을 권장한다.

## 4.4 실제 운용 실행 절차

### Terminal 0 — 로봇 브링업

```bash
ros2 launch open_manipulator_x_bringup hardware.launch.py
```

### Terminal 1 — 카메라 및 캘리브레이션

```bash
ros2 run waste_sorting aruco_homography_calibration
```

실행 후:

1. ArUco ID 1~4 인식
2. `Calibration LOCK` 확인
3. 필요 시 화면 클릭으로 좌표 정확도 검증
4. `r` 키로 재캘리브레이션
5. `q` 키로 종료

### Terminal 2 — 객체 인식

```bash
export ROBOFLOW_API_KEY='YOUR_KEY'

ros2 run waste_sorting detector
```

### Terminal 3 — 로봇 제어

```bash
ros2 run waste_sorting robot_control
```

실행 후 우선순위 표에서 `NEXT TARGET`을 확인하고 **Enter**를 입력하면 가장 가까운 물체 1개를 처리한다.

### 기동 순서

```text
브링업
  ↓
① aruco_homography_calibration
  ↓
② waste_detector
  ↓
③ waste_pick_node
```

①이 카메라를 소유하므로 ②보다 먼저 실행하는 것을 권장한다.

③은 `/detect_trash/nearest_target` 수신 전까지 대기하므로 ①, ②와의 실행 순서는 비교적 유연하다.

# 4.6 Model 설명

## 4.6.1 딥러닝 모델

Roboflow Inference를 이용하여 총 3개의 Object Detection 모델을 병렬 실행한다.

| 항목                   | Paper             | PET                                   | Can              |
| -------------------- | ----------------- | ------------------------------------- | ---------------- |
| Model ID             | `crumpledpaper/1` | `plastic-bottles-ip5yb-uziag-hg1ll/1` | `can-a8pgu/2`    |
| Task                 | Object Detection  | Object Detection                      | Object Detection |
| Confidence Threshold | 0.70              | **0.85**                              | 0.75             |
| 실행 방식                | 전용 스레드            | 전용 스레드                                | 전용 스레드           |
| API Key              | 필요                | 필요                                    | 필요               |

PET의 경우 투명성 및 반사 특성으로 인해 배경 오탐이 발생할 가능성이 있어 가장 높은 confidence threshold인 `0.85`를 적용하였다.

> 실제 프로젝트 보고서에서는 임계값별 Precision / Recall, 오탐 / 미탐 통계를 기반으로 선정 근거를 보완하는 것을 권장한다.

## 4.6.2 ArUco 마커 사양

| 항목                       | 값                                  |
| ------------------------ | ---------------------------------- |
| Dictionary               | `DICT_4X4_50`                      |
| 사용 ID                    | 1, 2, 3, 4                         |
| 코너 정밀화                   | `CORNER_REFINE_SUBPIX`             |
| Adaptive Threshold       | 3~53, step 4                       |
| `minMarkerPerimeterRate` | 0.005                              |
| 배치 기준                    | 마커 중심이 `robot_points` 좌표와 일치하도록 부착 |

마커의 크기 자체는 Homography 계산에 직접적인 영향을 주지 않으며, **마커 중심의 실제 위치 정확도**가 중요하다.

## 4.6.3 로봇 모델

| 항목                 | 내용                            |
| ------------------ | ----------------------------- |
| 로봇                 | OpenManipulator-X             |
| DOF                | 4-DOF + 1-DOF 그리퍼             |
| Actuator           | Dynamixel XM430 × 5           |
| 제어 인터페이스           | ros2_control                  |
| Arm Controller     | `joint_trajectory_controller` |
| Gripper Controller | `gripper_action_controller`   |
| 운동학 모델             | 경험적 근사 IK + 실측 거리 보정          |
| Home 자세            | `[0, -1.05, 0.35, 0.70]` rad  |
| 안전 비행 자세           | `[q1, -35°, -30°, +65°]`      |

본 프로젝트에서는 URDF 기반 정밀 IK 대신 **계산 단순성을 우선한 경험적 근사 IK**를 적용하고, 실측 기반 거리 보정을 결합하여 실제 작업에 필요한 정확도를 확보한다.

  ↓

  ↓

  ↓

  ↓
그리퍼 Open
  ↓

  ↓

  ↓
Home
