## 2.2 Node 표

| Node                           | 파일                                | 역할                                          | 실행 방식                          |
| ------------------------------ | --------------------------------- | ------------------------------------------- | ------------------------------ |
| `aruco_homography_calibration` | `aruco_homography_calibration.py` | 카메라 드라이버 + ArUco 캘리브레이션 + 좌표 변환 + 최근접 목표 선정 | GUI 루프 + `spin_once`           |
| `waste_detector`               | `detector.py`                     | 3-모델 병렬 추론, bbox 밑점 추출, 결과 발행               | `rclpy.spin` + 30 Hz 타이머 + GUI |
| `waste_pick_node`              | `robot_control.py`                | 목표 검증·보정, 근사 IK, 12단계 Pick & Place          | 별도 spin 스레드 + CLI input        |
| `/arm_controller`              | `ros2_control`                    | 4관절 궤적 추종                                   | -                              |
| `/gripper_controller`          | `ros2_control`                    | 그리퍼 위치/힘 제어                                 | -                              |
| `controller_manager`           | 브링업 패키지                           | 컨트롤러 관리                                     | -                              |
| `robot_state_publisher`        | 브링업 패키지                           | TF 발행                                       | -                              |

## 2.3 Topic 표

| Topic                          | Type                         | 방향         | QoS                       | 설명                                         |
| ------------------------------ | ---------------------------- | ---------- | ------------------------- | ------------------------------------------ |
| `/detect_trash/image_raw`      | `sensor_msgs/Image`          | ① → ②      | sensor_data (Best Effort) | 카메라 원본, `frame_id=trash_camera`, 실측 FPS 로그 |
| `/detect_trash/detections`     | `std_msgs/String`            | ② → ①      | depth 10                  | 전체 검출 목록(픽셀 좌표)                            |
| `/detect_trash/target_point`   | `geometry_msgs/PointStamped` | ① → RViz 등 | depth 10                  | 최근접 객체의 로봇 좌표, `frame_id=link1`            |
| `/detect_trash/nearest_target` | `std_msgs/String`            | ① → ③      | depth 10                  | 최근접 객체(종류 + 좌표 + 거리)                       |
| `/joint_states`                | 표준                           | 브링업 → 전체   | -                         | 로봇 관절 상태                                   |
| `/tf`                          | 표준                           | 브링업 → 전체   | -                         | 동적 TF                                      |
| `/tf_static`                   | 표준                           | 브링업 → 전체   | -                         | 정적 TF                                      |

### 2.3.1 `/detect_trash/detections` JSON 스키마

배열 형태로 여러 객체를 전달한다.

```json
[
  {
    "type": "paper",
    "class": "crumpled_paper",
    "confidence": 0.82,
    "x1": 100,
    "y1": 120,
    "x2": 180,
    "y2": 250,
    "center_x": 140,
    "center_y": 250
  }
]
```

| 필드                     | 타입     | 설명                      |
| ---------------------- | ------ | ----------------------- |
| `type`                 | string | `paper` / `pet` / `can` |
| `class`                | string | 모델의 원본 클래스명             |
| `confidence`           | float  | 임계값을 통과한 confidence     |
| `x1`, `y1`, `x2`, `y2` | int    | bbox 픽셀 좌표              |
| `center_x`, `center_y` | int    | **밑변 중앙점**              |

### 2.3.2 `/detect_trash/nearest_target` JSON 스키마

```json
{
  "type": "can",
  "class": "can",
  "confidence": 0.91,
  "x1": 250,
  "y1": 150,
  "x2": 320,
  "y2": 280,
  "center_x": 285,
  "center_y": 280,
  "pixel_x": 285,
  "pixel_y": 280,
  "x": 0.245,
  "y": -0.082,
  "distance": 0.258
}
```

| 필드                     | 타입     | 설명                       |
| ---------------------- | ------ | ------------------------ |
| `type`                 | string | 객체 종류                    |
| `class`                | string | 원본 클래스명                  |
| `confidence`           | float  | confidence               |
| `x1`, `y1`, `x2`, `y2` | int    | bbox 픽셀 좌표               |
| `center_x`, `center_y` | int    | bbox 밑변 중앙점              |
| `pixel_x`, `pixel_y`   | int    | Homography 변환에 사용된 픽셀 좌표 |
| `x`, `y`               | float  | 로봇 좌표(m)                 |
| `distance`             | float  | 로봇 원점으로부터의 거리(m)         |

## 2.4 Action 표

| Action                                    | Type                                 | 방향                     | 실행 방식                                          | 비고         |
| ----------------------------------------- | ------------------------------------ | ---------------------- | ---------------------------------------------- | ---------- |
| `/arm_controller/follow_joint_trajectory` | `control_msgs/FollowJointTrajectory` | ③ → arm_controller     | `send_goal_async` + `time.sleep(duration+0.3)` | **결과 미확인** |
| `/gripper_controller/gripper_cmd`         | `control_msgs/GripperCommand`        | ③ → gripper_controller | `send_goal_async` + `time.sleep(1.2)`          | **결과 미확인** |

> 현재 구현에서는 Action 결과를 직접 확인하지 않고 `sleep()`으로 다음 단계로 진행한다.

## 2.5 TF / Frame 표

| Frame                             | 발행 주체                   | 설명                                           |
| --------------------------------- | ----------------------- | -------------------------------------------- |
| `link1`                           | `robot_state_publisher` | **로봇 평면 좌표계 기준**, `target_point`의 `frame_id` |
| `trash_camera`                    | ① Image header          | 카메라 프레임 식별용, 정식 TF 미발행                       |
| `base_link` ~ `end_effector_link` | `robot_state_publisher` | 로봇 링크 체인                                     |

> 본 시스템은 카메라 외부 파라미터 TF 대신 **Homography가 카메라 ↔ 로봇 평면 변환을 대체**한다. 따라서 별도의 3D TF 체인이 필요하지 않다는 장점이 있지만, 평면 위 물체에만 유효하다는 제약이 있다.
