## 1.3 좌표계와 Homography 캘리브레이션

### 1.3.1 좌표계 정의

* **로봇 평면 좌표계**: joint1 축 부근을 원점으로 하는 작업판 평면 2D 좌표 (`frame_id: link1`)
* **카메라 픽셀 좌표계**: `u`(우), `v`(하), 640×480

### 1.3.2 ArUco 마커 배치

작업영역 크기: **0.4 m × 0.4 m**

| ID | 로봇 좌표 (m)   | 위치     |
| -- | ----------- | ------ |
| 1  | (0.4, 0.2)  | 오른쪽 아래 |
| 2  | (0.4, -0.2) | 왼쪽 아래  |
| 3  | (0.0, -0.2) | 왼쪽 위   |
| 4  | (0.0, 0.2)  | 오른쪽 위  |

### 1.3.3 변환 원리

4쌍의 대응점(픽셀 중심 ↔ 로봇 좌표)을 이용하여 `cv2.getPerspectiveTransform`으로 3×3 Homography 행렬 **H**를 1회 계산한다.

```text
[x_r, y_r, w]ᵀ = H · [u, v, 1]ᵀ

(X, Y) = (x_r / w, y_r / w)
```

#### 설계 특징

* 마커 4개(ID 1~4)가 모두 확보되는 순간 H를 계산하고 **LOCK**
* 이후 마커가 가려져도 계산된 H를 유지하여 조명 변화 및 일시적인 가림에 강건하게 동작
* 마커가 `0.5초 (marker_hold_sec)` 이내 재검출되면 이전 위치를 유지하여 순간적인 검출 실패 허용
* `r` 키를 이용하여 재캘리브레이션 가능
* ArUco 검출 파라미터 튜닝

  * adaptive threshold window: `3~53`, step `4`
  * subpixel corner refinement 적용

> **전제 조건 및 한계:** Homography는 평면 사영변환이므로 물체가 작업판 평면 위에 있을 때 정확하다. 따라서 detector에서는 bounding box의 **밑변 중앙점**을 기준점으로 사용한다.

## 1.4 객체 인식 파이프라인

### 1.4.1 3-모델 병렬 추론

| 종류    | Model ID                              | Confidence Threshold |
| ----- | ------------------------------------- | -------------------: |
| paper | `crumpledpaper/1`                     |                 0.70 |
| pet   | `plastic-bottles-ip5yb-uziag-hg1ll/1` |                 0.85 |
| can   | `can-a8pgu/2`                         |                 0.75 |

* `ThreadPoolExecutor(max_workers=3)`를 이용하여 3개 모델을 **비동기 병렬 실행**
* 각 모델은 이전 추론이 끝나는 즉시 **최신 프레임**으로 재추론
* 모델별 독립 추론 주기를 가지므로 느린 모델이 전체 파이프라인을 차단하지 않음
* 30 Hz 타이머에서 완료된 Future만 수거하여 화면 갱신 및 결과 발행

### 1.4.2 기준점(밑점) 설계

Bounding box에서 다음과 같이 기준점을 계산한다.

```python
center_x = (x1 + x2) / 2
center_y = y2
```

즉,

* `center_x`: bbox 가로 중앙
* `center_y`: bbox 밑변

#### 기준점 선정 근거

카메라가 비스듬히 내려다보는 구도에서 bbox 중심을 사용하면 물체 높이만큼 좌표가 카메라 반대쪽으로 밀릴 수 있다.

반면 bbox의 밑변 중앙점은 물체가 작업판과 접촉하는 위치에 가까우므로 작업판 평면상의 실제 위치를 나타내는 기준점으로 적합하다.

### 1.4.3 우선순위 결정

캘리브레이션 노드는 Homography로 변환된 모든 객체에 대해 원점으로부터의 거리를 계산한다.

```text
distance = √(x² + y²)
```

거리 기준 오름차순으로 정렬한 후 **가장 가까운 객체 1개**를 `/detect_trash/nearest_target`으로 발행한다.

가까운 물체부터 처리하여 로봇이 먼 물체로 이동할 때 작업영역 위를 가로지르는 동작을 최소화한다.

## 1.5 로봇 제어 전략

### 1.5.1 안전 비행 자세(Safe Flight Pose)

```text
joint2 = -35°
joint3 = -30°
joint4 = -(joint2 + joint3) = +65°
```

그리퍼가 수평을 유지하도록 구성한다.

물체 파지 후 이동 중에는 팔을 위로 접은 상태에서 **joint1만 회전**하여 작업판 위의 다른 물체와의 충돌 가능성을 최소화한다.

### 1.5.2 거리 기반 좌표 보정

근사 IK의 반경 방향 오차를 보상하기 위해 선형 가중 보정을 적용한다.

| 파라미터                 |                          값 | 설명               |
| -------------------- | -------------------------: | ---------------- |
| `REFERENCE_DISTANCE` | √(0.30² + 0.07²) ≈ 0.308 m | 보정이 0이 되는 기준 거리  |
| `NEAR_GAIN`          |                        3.0 | 기준보다 가까울 때 보정 강도 |
| Near limit           |                       -30% | 최대 축소 한계         |
| `FAR_GAIN`           |                        1.5 | 기준보다 멀 때 보정 강도   |
| Far limit            |                       +15% | 최대 확대 한계         |

보정식:

```text
(x', y') = (x, y) × (1 + weight_offset)
```

실측 데이터를 기반으로 조정한 캘리브레이션 성격의 보정이다.

### 1.5.3 근사 IK(`simple_ik_solver`)

해석적 IK 대신 어깨 높이 0.25 m를 기준으로 한 선형 근사식을 사용한다.

```text
joint1 = atan2(y, x)

joint2 = -0.20 + (0.25 - z) × 2.2

joint3 = 0.50 - (r - 0.22) × 2.0 + (0.25 - z) × 1.0

joint4 = -(joint2 + joint3)
```

`joint4`는 그리퍼가 항상 수평을 유지하도록 계산한다.

정밀도는 낮지만 계산이 단순하며, 거리 기반 좌표 보정과 결합하여 실용적인 정확도를 확보하는 구조이다.

### 1.5.4 파지 및 배치 파라미터

| 파라미터                 | 값              |
| -------------------- | -------------- |
| `PICK_Z` - can       | 0.02 m         |
| `PICK_Z` - pet       | 0.02 m         |
| `PICK_Z` - paper     | -0.07 m        |
| `Z_SAFE`             | 0.30 m         |
| Gripper OPEN         | 0.019 m        |
| Gripper HOLD         | 0.003 m        |
| Gripper `max_effort` | 100            |
| can BIN              | (-0.18, -0.13) |
| pet BIN              | (-0.18, 0.00)  |
| paper BIN            | (-0.18, 0.13)  |
| `TARGET_TIMEOUT`     | 2.0 s          |

분류함은 로봇 후방에 위치한다.

작업영역 검증:

```text
X ∈ [0, 0.4]
Y ∈ [-0.2, 0.2]
```

범위를 벗어난 목표는 거부한다.
